# grpc-from-zero — Day 26 of TechFromZero

A typed dictionary microservice with a real protobuf contract and a React UI consuming it via Connect-RPC — the same wire types compile into both ends.

- **Protocol:** Connect-RPC (HTTP/JSON over fetch). gRPC + gRPC-Web also supported on the same port.
- **Backend:** TypeScript + `@connectrpc/connect-node` on Node 22, fronting the free [api.dictionaryapi.dev](https://api.dictionaryapi.dev).
- **Frontend:** React + Vite + `@connectrpc/connect-web`. No proxy. No Envoy.
- **Codegen:** Buf + `protoc-gen-es` v2 → TS into `shared/gen/`.
- **Deploy:** Backend on Render (free Docker tier), frontend on Vercel.

The point of this project is to show what gRPC actually feels like in 2026: one `.proto` file, two ends, zero hand-written wire types, and the browser calls it directly.

---

## Quick start

```bash
# Install all workspaces (root + server + client)
npm install

# Regenerate TS from .proto (only needed if you edit proto/)
npm run generate

# Terminal 1 — Connect-RPC server
npm run dev:server   # http://localhost:4000

# Terminal 2 — React client
npm run dev:client   # http://localhost:5173
```

The Vite dev server proxies `/dictionary.v1.*` to the Connect-RPC server,
so the client's relative URL works in BOTH dev and prod.

### Try a Connect call

```bash
curl -s -X POST http://localhost:4000/dictionary.v1.DictionaryService/Define \
  -H "content-type: application/json" \
  -d '{"word":"ephemeral"}'
```

## RPCs this service exposes

```protobuf
service DictionaryService {
  rpc Define(DefineRequest) returns (DefineResponse);
  rpc WordOfTheDay(WordOfTheDayRequest) returns (WordOfTheDayResponse);
  rpc Health(HealthRequest) returns (HealthResponse);
}
```

Connect-RPC accepts three protocols on the same endpoint:

- **Connect** (HTTP/1.1 + JSON) — what the React UI uses
- **gRPC-Web** — for any browser client that prefers binary
- **gRPC** — for Go/Rust/Java clients hitting the same service

The server doesn't care which one you send. The handler stays the same.

## Deploy

### Backend on Render (free Docker tier)

1. Push to GitHub.
2. Render → **New + → Blueprint**, select the repo.
3. Render reads `render.yaml`, builds `server/Dockerfile`, deploys.
4. After deploy, `https://<your-app>.onrender.com/dictionary.v1.DictionaryService/Define` is live.

### Frontend on Vercel

```bash
cd client
vercel --prod --build-env VITE_RPC_URL=https://<your-app>.onrender.com
```

The build-env baking means the bundle ships with the right backend URL — no runtime config needed.

## Why Connect-RPC instead of gRPC-Web + Envoy?

Classic gRPC-Web requires an Envoy sidecar to translate browser HTTP/1.1
into gRPC HTTP/2. That's a second container, a second config file, and a
second thing to debug at 2 a.m.

Connect-RPC accepts plain HTTP/1.1 + JSON on the same endpoint as gRPC.
Same `.proto`, same generated TS, no proxy. The React app calls
`client.define({ word })` and the server processes it like any other gRPC
call. One container deploys instead of two.
